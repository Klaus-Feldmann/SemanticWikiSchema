# Query capabilities and delayed processing

sws-get-query-capabilities reports Cypher/Neo4j and SWS SPARQL configuration separately as configured, not-configured or unknown. A harmless empty parser query is rejected before any store access: the known unconfigured message establishes absence; the known empty-query or permission-denied message establishes that the backend was registered. Localized messages come from the wiki itself. Unknown output, unavailable authentication or a failed request does not establish absence. No actual graph query, page save or rebuild is performed during discovery. Configuration checks are cached for at most 60 seconds per wiki/credential context; unknown results for 5 seconds. refresh=true checks again immediately. Pure MCP discovery does not perform this authenticated probe: it happens on first wiki use or on demand.

A known missing backend hides its tool and refuses stale calls. Unknown configurations remain conditional hints; the requested read-only graph query is sent normally, with an advisory, and actual endpoint errors are returned. get-agent-context lists confirmed tools separately from conditional graph tools. A shared multi-wiki tool list can still include a graph tool enabled for another wiki; the targeted wiki is always checked.

Configured means only that SWS registered the backend. Connectivity and token authorization are tested by the actual query, and a transient connection failure is not reclassified as missing configuration. The SPARQL wrapper addresses the first store configured in SWS, not the separate Wikibase query service. Determine the actual RDF projection before building field queries.

All indexed/graph query results have unknown freshness until suitable evidence is checked. runJobs can delay SMW, SWS listings and RDF/Neo4j projections. Empty results are not proof of absence. A successful query is not proof that background work completed. For a known page/entity, read the current SWS entity and use sws-get-processing-status. Its per-page processing and observed SMW write evidence cannot prove global queue completion or that every index has caught up. The patch never triggers a rebuild or changes a schema to fix apparent absence.

For ASK results only, the MCP adapter normalizes an empty head array from PHP JSON re-encoding to the W3C empty head object and reports this normalization. Boolean values and bindings are preserved.
